# NLO Letters — source

Referral letters for other offices (extraction, oral hygiene, exposure, orthognathic evaluation, cosmetic bonding, evaluation for cavity, radiographic evaluation, TAD placement, TADs for MARPE). It replaces the Edge mail-merge letters for these: pick the letter, type the patient's name and date of birth, pick the doctor, click the teeth and the details, then print or save as a PDF. The page people open is `../nlo-letters.html` (built from here). It uses the same Firebase project (`nlo-cases`), the same logins and the same office key as NLO Cases.

- **Nothing about a patient is saved or sent.** The name, date of birth, letter text and any attached x-ray live only in the page and are cleared on Lock, on the idle lock, and when the page closes. The tests check that none of it reaches Firestore or browser storage.
- **What is stored:** the doctor directory, one sealed record per doctor (`refDocs`), and the owner's letter settings (`refCfg/office`), both encrypted in the browser with the office key. Staff can add, correct and hide doctors; only the owner can delete one, import the Edge list, or change Settings.
- `src/` — `core.js` (crypto helpers, CSV; the same as NLO Leads), `letters.js` (the nine letters and their wording, the teeth, the directory's shape, the Edge import; pure functions), `backend.js` (Firebase: sign-in, key ring, the sealed directory), `demo.js` (`?demo`, made-up doctors), `ui.js`, `style.css`, `template.html`.
- **Wording.** The extraction letter follows the office's Edge merge letter "Pt Extraction Request" (version 5, June 2026); the other six are written in the same voice. A choice is `[key, button label, words]` in `LETTERS`; `build()` turns the picked choices into paragraphs. Every tooth is printed as number **and** name ("#5 (upper right first premolar)") so a number can't be misread; numbering is Universal or FDI (Settings sets the default, the chart can switch per letter). `toothCount()` makes the sentences agree with one tooth or several. The exposure letter's chart offers adult teeth only (exposure is of adult teeth) and has a second chart, "Teeth to remove at the same visit", for baby or adult teeth the surgeon should extract; when any are picked the subject becomes "Referral for Surgical Exposure and Extraction".
- **The doctor list** comes from Edge: Reporting → Professional List → tick the professional types → View → Export → Excel. That export is three to five rows per doctor, so it is reshaped into `NLO_Provider_Directory_from_Edge.csv` (columns Type, Last, First, Practice, Address, City/State/Zip, Email, Phone, Edge note), which the owner imports from Doctors → Import from Edge. Importing again skips doctors already in the directory. Edge prints the email **or** the phone, never both.
- Security rules are shared with NLO Cases: `../nlo-cases-src/firestore.rules` (the Letters block follows the Leads block). `OWNER_EMAIL=<Dr. A's sign-in email> python3 build.py` writes `dist/firestore.rules` to publish. Until the new rules are published the directory can't be read; the page says so and letters can still be written by adding the doctor by hand.
- `python3 build.py` → `dist/nlo-letters.html`. `fbconfig.js` holds the live Firebase web config (public by design; security is the rules plus encryption).
- Not built yet: sending from Outlook (needs an app registration in Microsoft 365 and encrypted sending), and a sent-letters log.
- Tests use made-up data only. Same tools as NLO Cases (`npm install` its `package.json`), plus a static server on :8765 serving `dist/` with `nlo-cases.html` copied in:
  - `node test/unit.test.js` (wording, teeth, import)
  - `NO_PROXY=localhost,127.0.0.1 npx firebase emulators:exec --only firestore,auth --project demo-nlo-cases "node test/rules.test.mjs"`, then the same line again with `"CHROME=<chrome> node test/e2e.js"` (each needs a fresh emulator)
  - `CHROME=<chrome> node test/shot.js <folder>` saves screenshots and each letter as a PDF, for looking at.
