# NLO Cases — source

Encrypted case tracker that replaces Asana + Tally for patient cases. The page people open is `../nlo-cases.html` (built from here).

- `src/` — `core.js` (config, case types/stages, crypto helpers, Asana parsing), `backend.js` (Firebase: sign-in, key ring, encrypted cases, enforced version history, team, key change), `demo.js` (`?demo`, made-up data), `ipr.js` (read-only link to the IPR Tracker's database), `ui.js`, `logos.js` (company logos for the case-type tiles, generated), `caseform.js` (tap-first New case form), `admin.js`, `mail.js` (lab-email updates: opens the sealed emails the Gmail script forwards, reads the uLab / Partners / Oliv / Angel formats, matches each patient to a case — lab case # first, then name — and moves cases forward; the Today card for updates that need a case; the Team & security card that hands out the script), `style.css`, `template.html`.
- `logos/<type>-source.png` — the company logos Amir pasted (Oliv, Angel, uLab, Invisalign, InSmile); `python3 tools/logos.py` trims them, makes the white transparent and writes `src/logos.js` (data: URLs, allowed by the page's CSP). Add a logo by saving it as `logos/<type>-source.png` (type = the tile key, e.g. `oliv`) and re-running it.
- `mail/` — the Google Apps Script that runs in each office Gmail account (every 10 minutes): `script.js` (the script), `seal.js` (BigInt-free P-256 ECDH + HKDF-SHA256 + AES-256-GCM, the same sealing as the app's `Crypto.sealTo`, since Apps Script has no WebCrypto), and `nlo-cases-mail.gs`, built by `node tools/build-mail.js` (bundles `seal.js` with esbuild and checks it against WebCrypto known answers). The script forwards whole lab emails sealed to the office inbox key, using its own robot login that can only add sealed items to `inbox/` and note its check-ins in `mailbeat/`; all parsing is in the app, so a new lab format only needs an app update. The app hands out a copy with the robot login filled in (Team & security → Email updates).
- `firestore.rules` — security rules; `__OWNER_EMAIL__` is filled in by the build.
- `python3 build.py` → `dist/nlo-cases.html` + `dist/firestore.rules`. `fbconfig.js` holds the live Firebase web config (project `nlo-cases`; public by design — security is the rules plus encryption). For the rules that go live, build with `OWNER_EMAIL=<Dr. A's sign-in email>` and publish `dist/firestore.rules` in the Firebase console (Firestore → Rules). Without `fbconfig.js` the page is demo-only.
- Tests (need `npm i` with `package.json` — firebase-tools, @firebase/rules-unit-testing, firebase@12, firebase10, playwright, and for the email script elliptic, aes-js, hash.js, esbuild — and a static server on :8765 serving `dist/`):
  `NO_PROXY=localhost,127.0.0.1 npx firebase emulators:exec --only firestore,auth,database --project demo-nlo-cases "node test/rules.test.mjs && node test/e2e.js"`, plus `node test/ipr_parity.js`, `node test/demo_smoke.js` and `node test/mail_script.js` (the email script against the app's own crypto and a fake Firestore). `test/gas.js` mocks Apps Script; the e2e test runs the handed-out script against the emulators with made-up patients.
